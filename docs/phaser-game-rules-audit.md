# Аудит игровых правил для переноса на Phaser

Документ фиксирует правила текущей Python/Telegram-версии Cars RNG, которые нужно перенести в Phaser/Yandex Games. Это результат этапа 1, пункта 2 из `PHASER_YANDEX_MIGRATION_PLAN.md`.

## Источники

- `game/engine.py`
- `handlers/spin.py`
- `handlers/cases.py`
- `handlers/upgrades.py`
- `handlers/inventory.py`
- `handlers/leaderboard.py`
- `storage/db.py`

## 1. Обычный спин

Источник: `SpinEngine.spin()`.

Правила:

1. Обычный спин использует каталог машин из `get_all_cars()`.
2. Машины с редкостью `Эксклюзивный` исключаются из обычного спина.
3. Перед спином проверяется `chance_mult`.
4. `chance_mult` должен быть положительным конечным числом.
5. За попытку выбирается случайная машина из обычного пула.
6. Для выбранной машины считается порог выигрыша:

```text
win_threshold = car.base_chance * 100_000 * chance_mult
```

7. Генерируется случайное целое число:

```text
roll = random integer from 0 to 10_000_000
```

8. Если `roll <= win_threshold`, машина выпадает.
9. Если машина не выпала, движок пробует снова.
10. Максимальное число попыток: `10_000`.
11. Если за `10_000` попыток ничего не выпало, текущая версия выбрасывает ошибку.

Особенность текущего поведения:

- В отличие от старого README, текущий `SpinEngine.spin()` всегда должен вернуть машину или ошибку.
- Сценария "ничего не выпало" в актуальном коде Telegram-бота уже нет.

Рекомендация для Phaser:

- Сохранить текущую механику, чтобы игрок всегда получал результат спина.
- Ошибку после `MAX_ATTEMPTS` заменить на fallback: выдать самую частую обычную машину или повторить безопасный roll, чтобы в production не ломать UX.

Предлагаемая TypeScript-сигнатура:

```ts
export function spin(cars: Car[], chanceMult: number, rng: Rng): Car;
```

## 2. Pending-награда после одиночного результата

Источники:

- `handlers/spin.py`
- `storage/db.py`
- `handlers/cases.py`

Правила:

1. После одиночного спина выпавшая машина сохраняется как pending.
2. После одиночного открытия кейса выпавшая машина тоже сохраняется как pending.
3. Пока есть pending-машина, новый одиночный спин запрещен.
4. Пока есть pending-машина, открытие кейса запрещено.
5. Игрок должен выбрать одно из действий:
   - оставить;
   - продать.
6. При выборе `Оставить`:
   - если гараж не заполнен, машина добавляется в инвентарь;
   - pending очищается;
   - если гараж заполнен, действие не выполняется.
7. При выборе `Продать`:
   - игрок получает `car.value`;
   - pending очищается.

Рекомендация для Phaser:

- Сохранять pending-награду в `SaveData`, чтобы игрок не потерял результат при закрытии вкладки.
- Не давать запускать новый одиночный спин или одиночный кейс, пока pending-награда не обработана.
- Для UX можно показывать pending-карточку сразу при запуске игры.

Предлагаемая TypeScript-модель:

```ts
export type PendingReward = {
  source: "spin" | "case";
  carId: string;
  createdAt: number;
};
```

## 3. Оставить pending-машину

Источник: `Database.keep_pending_car()`.

Правила:

1. Проверить наличие pending-машины.
2. Проверить количество машин в инвентаре.
3. Если `inventory.length >= garageCap`, машина не добавляется.
4. Если место есть:
   - создать запись в инвентаре;
   - удалить pending-машину;
   - баланс не меняется.

Предлагаемая TypeScript-сигнатура:

```ts
export function keepPendingReward(save: SaveData): KeepResult;
```

Возможные результаты:

```ts
export type KeepResult =
  | { status: "ok"; added: InventoryCar }
  | { status: "no-pending" }
  | { status: "garage-full" };
```

## 4. Продать pending-машину

Источник: `Database.sell_pending_car()`.

Правила:

1. Проверить наличие pending-машины.
2. Найти машину в каталоге по pending `carId`.
3. Увеличить баланс на `car.value`.
4. Очистить pending.

Предлагаемая TypeScript-сигнатура:

```ts
export function sellPendingReward(save: SaveData, cars: Car[]): SellPendingResult;
```

Возможные результаты:

```ts
export type SellPendingResult =
  | { status: "ok"; car: Car; balance: number }
  | { status: "no-pending" };
```

## 5. Продажа машины из гаража

Источник: `Database.sell_inventory_car()`.

Правила:

1. Игрок выбирает конкретную машину по `inventoryId`.
2. Если такой машины нет, действие не выполняется.
3. Машина удаляется из инвентаря.
4. Баланс увеличивается на `car.value`.

Предлагаемая TypeScript-сигнатура:

```ts
export function sellInventoryCar(save: SaveData, inventoryId: string, cars: Car[]): SellInventoryResult;
```

## 6. Автообработка машины при заполненном гараже

Источники:

- `_process_auto_spin_car_conn()`
- `process_auto_spin_car()`
- `process_pending_auto_spin_car()`
- `open_case_bulk()`

Эта логика используется:

- автокруткой;
- массовым открытием кейсов;
- обработкой pending при запуске автокрутки.

Правила:

1. Если в гараже есть место:
   - новая машина добавляется в гараж;
   - баланс не меняется;
   - результат: `added`.
2. Если гараж заполнен:
   - находится самая дешевая машина в гараже;
   - при равной цене выбирается более старая запись по `id`.
3. Если самая дешевая машина дороже новой:
   - новая машина продается;
   - баланс увеличивается на `newCar.value`;
   - гараж не меняется;
   - результат: `sold_new`.
4. Иначе:
   - самая дешевая машина продается;
   - баланс увеличивается на `cheapestCar.value`;
   - новая машина добавляется в гараж;
   - результат: `replaced`.

Важная деталь:

- При равной цене текущая логика заменяет старую дешевую машину на новую, потому что условие продажи новой машины: `cheapest_car.value > car.value`.
- Если `cheapest_car.value == car.value`, выполняется ветка `replaced`.

Предлагаемая TypeScript-сигнатура:

```ts
export function processCarIntoGarage(save: SaveData, car: Car): ProcessCarResult;
```

Возможные результаты:

```ts
export type ProcessCarResult =
  | { action: "added"; car: Car; balance: number; count: number }
  | { action: "sold_new"; car: Car; balance: number; count: number }
  | { action: "replaced"; car: Car; soldCar: Car; balance: number; count: number };
```

## 7. Автокрутка

Источник: `handlers/spin.py`.

Текущие правила Telegram-версии:

1. Автокрутка запускается по callback `autospin:start`.
2. На одного пользователя может быть только одна активная задача автокрутки.
3. Интервал между спинами: `3` секунды.
4. Если есть pending-машина, при запуске автокрутки она сначала автоматически обрабатывается через логику автообработки гаража.
5. Каждый автоспин:
   - получает игрока;
   - выполняет обычный `spin(chance_mult)`;
   - обрабатывает машину через автообработку гаража;
   - отправляет результат.
6. Автокрутка останавливается вручную.

Рекомендация для Phaser:

- Для первого релиза автокрутку можно отложить.
- Если переносить, лучше сделать ее не фоновой задачей, а игровым режимом в `SpinScene`.
- Обязательно ограничить частоту сохранений, чтобы не сохранять прогресс в Yandex Player Data каждые 3 секунды бесконечно.

## 8. Обычные кейсы

Источники:

- `CaseEngine.open_case()`
- `handlers/cases.py`

Текущие кейсы:

| ID | Название | Минимальная редкость | Цена |
|---|---|---|---:|
| `case:uncommon` | Необычный+ кейс | `Необычный` | `100_000` |
| `case:rare` | Редкий+ кейс | `Редкий` | `2_500_000` |

Правила пула:

1. Берутся все машины, у которых `RARITY_RANKS[car.rarity] >= RARITY_RANKS[minRarity]`.
2. Эксклюзивные машины исключаются.
3. Вес машины равен:

```text
weight = max(car.base_chance, 0.0001)
```

4. Машина выбирается через weighted random.

Одиночное открытие:

1. Проверяется наличие pending-машины.
2. Проверяется достаточность денег.
3. Списывается стоимость кейса.
4. Выбранная машина сохраняется как pending.
5. Игрок выбирает `Оставить` или `Продать`.

Массовое открытие:

1. Поддерживаются только `x10` и `x100`.
2. Проверяется наличие pending-машины.
3. Проверяется достаточность денег.
4. Списывается `cost * count`.
5. Все машины автоматически обрабатываются через `processCarIntoGarage`.
6. Pending не создается.
7. В summary сохраняются:
   - `opened`;
   - `spent`;
   - `added`;
   - `replaced`;
   - `sold_new`;
   - `earned`;
   - `balance`;
   - `best_cars`.
8. `best_cars` сортируются по `value DESC` и обрезаются до 10 машин.

## 9. Эксклюзивные кейсы

Источники:

- `CaseEngine.open_exclusive_case()`
- `CaseEngine._exclusive_case_pool()`
- `handlers/cases.py`

Правила:

1. Для каждой эксклюзивной машины создается отдельный кейс.
2. Стоимость каждого эксклюзивного кейса: `4_000_000`.
3. Пул эксклюзивного кейса:
   - все машины редкости `Редкий` и выше без эксклюзивных;
   - целевая эксклюзивная машина.
4. Вес каждой машины:

```text
weight = max(car.base_chance, 0.0001)
```

5. Поддерживается одиночное открытие.
6. Поддерживаются `x10` и `x100`.
7. Одиночное открытие создает pending.
8. Массовое открытие автоматически обрабатывает все машины.

## 10. Улучшение шанса

Источники:

- `handlers/upgrades.py`
- `Database.buy_chance_upgrade()`

Константы:

```text
CHANCE_BASE_COST = 100_000
CHANCE_STEP = 0.1
```

Правила:

1. Цена следующего улучшения:

```text
chance_cost = int(CHANCE_BASE_COST * player.chance_mult)
```

2. Если денег недостаточно, покупка не выполняется.
3. Если денег достаточно:
   - баланс уменьшается на `chance_cost`;
   - `chance_mult` увеличивается на `0.1`.

Рекомендация для Phaser:

- Из-за float-арифметики хранить множитель как целые шаги или аккуратно округлять для UI.
- Например, хранить `chanceLevel`, а `chanceMult = 1 + chanceLevel * 0.1`.

## 11. Расширение гаража

Источники:

- `handlers/upgrades.py`
- `Database.buy_garage_upgrade()`

Константы:

```text
GARAGE_BASE_COST = 75_000
GARAGE_COST_STEP = 50_000
GARAGE_STEP = 5
INITIAL_GARAGE_CAP = 20
```

Правила:

1. Уровень расширения:

```text
garage_level = max(0, (garage_cap - INITIAL_GARAGE_CAP) // GARAGE_STEP)
```

2. Цена следующего расширения:

```text
garage_cost = GARAGE_BASE_COST + garage_level * GARAGE_COST_STEP
```

3. Если денег недостаточно, покупка не выполняется.
4. Если денег достаточно:
   - баланс уменьшается на `garage_cost`;
   - `garage_cap` увеличивается на `5`.

## 12. Инвентарь и сортировка

Источник: `Database.get_inventory()`.

Текущая сортировка:

1. `Легендарный`
2. `Эксклюзивный`
3. `Эпический`
4. `Редкий`
5. `Необычный`
6. `Обычный`
7. неизвестная редкость

Внутри редкости:

1. `value DESC`;
2. `id ASC`.

Рекомендация для Phaser:

- Сохранить сортировку для привычного поведения.
- В UI можно дополнительно дать переключатели сортировки, но дефолт оставить таким же.

## 13. Лидерборд

Источник: `Database.get_leaderboard()`.

Правила:

1. Учитываются только машины в инвентаре.
2. Очки игрока:

```text
total_points = SUM(inventory.points)
```

3. Сортировка:
   - `total_points DESC`;
   - `user_id ASC` как tie-breaker в Telegram-версии.
4. В текущем коде выводится топ 10.

Рекомендация для Yandex Games:

- Отправлять `total_points` в Yandex Leaderboards.
- Tie-breaker будет зависеть от платформы Яндекса.
- Локально пересчитывать score после каждого изменения гаража.

## 14. Стартовые значения игрока

Источник: `Player` и SQL-схема `users`.

Стартовые значения:

| Параметр | Значение |
|---|---:|
| `money` | `0` |
| `chance_mult` | `1.0` |
| `garage_cap` | `20` |
| `display_name` | `Игрок` |
| `inventory` | пустой |
| `pending` | пустой |

## 15. Денежные операции

Все изменения баланса:

| Действие | Изменение |
|---|---:|
| Продажа pending-машины | `+ car.value` |
| Продажа машины из гаража | `+ car.value` |
| Продажа новой машины при полном гараже | `+ newCar.value` |
| Замена дешевой машины при полном гараже | `+ cheapestCar.value` |
| Одиночный Необычный+ кейс | `- 100_000` |
| Одиночный Редкий+ кейс | `- 2_500_000` |
| Одиночный эксклюзивный кейс | `- 4_000_000` |
| Массовые кейсы | `- cost * count`, затем возможные продажи |
| Улучшение шанса | `- int(100_000 * chance_mult)` |
| Расширение гаража | `- (75_000 + garage_level * 50_000)` |

## 16. Правила, которые стоит изменить при переносе

Эти места лучше осознанно улучшить в Phaser-версии:

1. `chance_mult` лучше хранить как уровень, а не float.
2. Ошибку `Spin did not produce a car within the attempt limit` лучше заменить на безопасный fallback.
3. Автокрутку лучше не сохранять как бесконечный фоновой процесс.
4. Массовые кейсы должны сохранять прогресс одним батчем.
5. Pending-награду нужно сохранять между сессиями.
6. В сохранениях хранить `carId`, а не копию полей машины.

## Минимальный набор правил для первого Phaser-релиза

Для первого релиза обязательно перенести:

1. Обычный спин.
2. Pending-награду.
3. Оставить/продать pending-машину.
4. Гараж и лимит гаража.
5. Продажу из гаража.
6. Улучшение шанса.
7. Расширение гаража.
8. Подсчет очков лидерборда.

Можно перенести после базовой версии:

1. Кейсы.
2. Массовое открытие кейсов.
3. Эксклюзивные кейсы.
4. Автокрутку.
