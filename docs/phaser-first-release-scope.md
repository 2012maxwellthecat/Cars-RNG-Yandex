# Состав первого релиза Phaser-версии

Документ фиксирует решение по этапу 1, пункту 3 из `PHASER_YANDEX_MIGRATION_PLAN.md`: какие возможности входят в первый релиз Cars RNG для Яндекс Игр, а какие переносятся на следующие версии.

## Цель первого релиза

Собрать небольшую, но полноценную браузерную версию Cars RNG, которая:

- запускается как HTML5-игра;
- работает без Telegram, Python и SQLite;
- имеет базовый игровой цикл;
- сохраняет прогресс;
- может пройти техническую проверку Яндекс Игр;
- оставляет место для расширения кейсами, рекламой, событиями и платежами.

Главная идея первого релиза: не пытаться сразу перенести весь Telegram-бот, а выпустить устойчивое ядро игры.

## Входит в первый релиз

### 1. Главное меню

Обязательные элементы:

- кнопка `Крутить`;
- кнопка `Гараж`;
- кнопка `Улучшения`;
- кнопка `Лидерборд`;
- отображение баланса;
- отображение количества машин в гараже.

Задача:

- дать игроку быстрый доступ к основным действиям;
- заменить Telegram reply-кнопки полноценным игровым меню.

### 2. Обычный спин

Обязательные правила:

- использовать обычный пул машин без `Эксклюзивный`;
- применять `chanceMult`;
- использовать формулу из текущего `SpinEngine`;
- выдавать одну машину за спин;
- показывать карточку выпавшей машины.

Минимальный UX:

- кнопка запуска спина;
- короткая анимация ожидания или прокрутки;
- карточка результата;
- кнопки `Оставить` и `Продать`.

### 3. Pending-награда

Обязательные правила:

- после спина машина становится pending-наградой;
- пока pending-награда не обработана, новый спин недоступен;
- pending-награда сохраняется между сессиями;
- при запуске игры pending-награда показывается игроку.

Почему это важно:

- это сохраняет ключевую механику текущего Telegram-бота;
- игрок не теряет выпавшую машину при перезагрузке страницы.

### 4. Оставить или продать машину

Обязательные действия:

- `Оставить`: добавить машину в гараж, если есть место;
- `Продать`: начислить `car.value` на баланс;
- после любого успешного действия очистить pending-награду;
- сохранить прогресс.

Если гараж заполнен:

- при ручном выборе `Оставить` показать сообщение, что гараж полон;
- игрок должен продать pending-машину или освободить место.

### 5. Гараж

Обязательные возможности:

- показать список или сетку машин игрока;
- показать заполненность гаража;
- открыть карточку машины;
- продать машину из гаража;
- сортировать по текущей дефолтной логике.

Дефолтная сортировка:

1. `Легендарный`
2. `Эксклюзивный`
3. `Эпический`
4. `Редкий`
5. `Необычный`
6. `Обычный`

Внутри редкости:

- цена по убыванию;
- более раннее получение выше при равной цене.

### 6. Улучшения

В первый релиз входят два улучшения.

Улучшение шанса:

- базовая цена: `100_000`;
- шаг: `+0.1`;
- цена: `100_000 * chanceMult`;
- при покупке баланс уменьшается, шанс увеличивается.

Расширение гаража:

- стартовая вместимость: `20`;
- шаг расширения: `+5`;
- базовая цена: `75_000`;
- шаг цены: `50_000`;
- цена: `75_000 + garageLevel * 50_000`.

Рекомендация для реализации:

- хранить `chanceLevel`, а не только float `chanceMult`;
- `chanceMult` вычислять как `1 + chanceLevel * 0.1`.

### 7. Сохранение прогресса

Обязательные данные:

- версия сохранения;
- баланс;
- уровень шанса или `chanceMult`;
- вместимость гаража;
- инвентарь;
- pending-награда;
- базовая статистика.

Минимальная схема:

```ts
export type SaveData = {
  version: number;
  money: number;
  chanceLevel: number;
  garageCap: number;
  inventory: InventoryCar[];
  pendingReward: PendingReward | null;
  stats: {
    spins: number;
    carsSold: number;
  };
};
```

Сохранения:

- локальная разработка: `localStorage`;
- Яндекс Игры: Yandex Player Data;
- если SDK недоступен, игра должна продолжать работать через fallback.

### 8. Базовый лидерборд

В первый релиз входит базовая интеграция лидерборда, если SDK уже подключен.

Формула:

```text
score = сумма points всех машин в гараже
```

Минимальное поведение:

- пересчитывать score после изменения гаража;
- отправлять score в Yandex Leaderboards;
- показывать топ, если SDK доступен;
- при локальном запуске показывать fallback-сообщение.

Если лидерборд начнет тормозить выпуск, его можно оставить как подготовленную сцену без публикации score до второго релиза.

## Не входит в первый релиз

### Кейсы

Откладываются:

- Необычный+ кейс;
- Редкий+ кейс;
- эксклюзивные кейсы;
- массовое открытие x10/x100.

Причина:

- кейсы требуют отдельного UX, summary-экранов и аккуратной экономики;
- базовый игровой цикл может работать без них.

### Автокрутка

Откладывается.

Причина:

- в Telegram-боте автокрутка работает как фоновая задача;
- в браузерной игре ее нужно переосмыслить как активный режим;
- частые сохранения могут быть плохой идеей для Yandex Player Data.

### Реклама

Откладывается:

- fullscreen ads;
- rewarded ads.

Причина:

- сначала нужно пройти базовую техническую проверку;
- рекламу проще добавлять после стабильного игрового цикла.

### Платежи

Откладываются полностью.

Причина:

- платежи требуют отдельного баланса экономики и проверки;
- для первого релиза достаточно игровой валюты без доната.

### События и достижения

Откладываются:

- временные события;
- достижения;
- специальные коллекции;
- ежедневные награды.

Причина:

- это хороший контент для обновлений, но не базовый функционал.

## Сцены первого релиза

Обязательные сцены:

| Сцена | Статус | Назначение |
|---|---|---|
| `BootScene` | обязательно | Инициализация SDK, сохранений и базового состояния |
| `PreloadScene` | обязательно | Загрузка ассетов |
| `MenuScene` | обязательно | Главное меню |
| `SpinScene` | обязательно | Спин и pending-награда |
| `GarageScene` | обязательно | Инвентарь и продажа машин |
| `UpgradesScene` | обязательно | Улучшения шанса и гаража |
| `LeaderboardScene` | желательно | Лидерборд или fallback |

Не создавать в первом релизе:

- `CasesScene`;
- рекламные pop-up flow;
- магазин платежей;
- сцены событий.

## Минимальный игровой цикл

Первый релиз должен поддерживать такой цикл:

1. Игрок запускает игру.
2. Игра загружает сохранение.
3. Игрок нажимает `Крутить`.
4. Игра показывает выпавшую машину.
5. Игрок выбирает `Оставить` или `Продать`.
6. Если машина оставлена, она появляется в гараже.
7. Если машина продана, баланс увеличивается.
8. Игрок покупает улучшения за баланс.
9. Улучшения влияют на будущие спины или размер гаража.
10. Прогресс сохраняется.

## Критерии готовности первого релиза

Функциональные:

- новый игрок получает стартовое сохранение;
- спин выдает машину;
- pending-награда не теряется после перезагрузки;
- машину можно оставить;
- машину можно продать;
- гараж показывает актуальный список;
- продажа из гаража начисляет деньги;
- улучшение шанса работает;
- расширение гаража работает;
- прогресс сохраняется и загружается.

Технические:

- игра запускается через `npm run dev`;
- production-сборка создается через `npm run build`;
- папка `dist/` открывается как статическая HTML5-игра;
- нет зависимости от Python, Telegram и SQLite;
- SDK-обертка имеет fallback для локального режима;
- игра адаптируется под мобильный экран;
- изображения машин загружаются без критических пропусков.

Для Яндекс Игр:

- SDK инициализируется до обращения к Player Data;
- игра не ломается, если пользователь не авторизован;
- сохранение работает через Yandex Player Data или fallback;
- игра корректно работает в iframe;
- нет блокирующих внешних запросов к неразрешенным источникам;
- интерфейс управляется мышью и touch.

## Риски первого релиза

### Слишком большой каталог машин

Проблема:

- загрузка всех изображений сразу может замедлить старт.

Решение:

- для первого релиза можно грузить изображения по мере необходимости;
- на старте грузить только UI и первые нужные ассеты;
- изображения гаража подгружать лениво.

### Сохранения через SDK

Проблема:

- SDK недоступен при локальной разработке;
- игрок может быть не авторизован.

Решение:

- обязательный fallback на `localStorage`;
- отдельный `saveService`, который скрывает источник сохранения.

### Float-значения шанса

Проблема:

- `chanceMult += 0.1` может давать некрасивые значения в JS.

Решение:

- хранить `chanceLevel`;
- вычислять `chanceMult` из уровня.

### Отсутствие кейсов в первом релизе

Проблема:

- часть текущего функционала Telegram-бота не попадет в первую web-версию.

Решение:

- оставить места в меню/архитектуре;
- добавить кейсы вторым релизом после стабилизации сохранений и гаража.

## Решение

Первый релиз Phaser-версии включает:

- главное меню;
- обычный спин;
- pending-награду;
- оставить/продать;
- гараж;
- продажу из гаража;
- улучшение шанса;
- расширение гаража;
- сохранение прогресса;
- базовый лидерборд как желательно, но не блокирующее требование.

Во второй релиз переносятся:

- кейсы;
- x10/x100 открытия;
- эксклюзивные кейсы;
- автокрутка;
- реклама;
- платежи;
- события;
- достижения.
