# План перевода Cars RNG на Phaser для Яндекс Игр

## Цель

Создать отдельную браузерную версию Cars RNG на Phaser для публикации в Яндекс Играх. Текущий Python/Telegram-проект остается источником игровой логики и данных, но новая версия должна быть полноценной HTML5-игрой: с визуальным интерфейсом, сохранениями через Yandex Games SDK, лидербордом и подготовкой к модерации платформы.

## Рекомендуемый стек

- Phaser 4.2.1
- TypeScript
- Vite
- Yandex Games SDK
- Сборка в статический `dist/`
- Сохранения через Yandex Player Data
- Fallback-сохранения через `localStorage`

Yandex Games SDK не привязан к конкретной версии Phaser. Главное требование: игра должна быть HTML5/JavaScript-приложением, корректно подключать SDK и работать внутри iframe Яндекс Игр.

## Этап 1. Аудит текущего проекта

1. Зафиксировать текущие игровые сущности: готово, см. `docs/phaser-game-entities-audit.md`.
   - машина;
   - игрок;
   - инвентарная машина;
   - редкость;
   - баланс;
   - гараж;
   - множитель шанса.

2. Перенести правила из Python: готово, см. `docs/phaser-game-rules-audit.md`.
   - обычный спин;
   - исключение эксклюзивных машин из обычного спина;
   - кейсы;
   - x10/x100 открытие кейсов;
   - продажа машин;
   - автозамена дешевой машины при заполненном гараже;
   - улучшение шанса;
   - расширение гаража;
   - подсчет очков для лидерборда.

3. Решить состав первого релиза: готово, см. `docs/phaser-first-release-scope.md`.
   - обязательное: спин, гараж, продажа, улучшения, сохранение прогресса;
   - желательно: кейсы, лидерборд;
   - позже: rewarded ads, платежи, события, достижения.

## Этап 2. Создание нового Phaser-проекта

Статус: готово, каркас создан в `yandex-game/`.

Создать отдельную папку, например:

```text
yandex-game/
```

Предлагаемая структура:

```text
yandex-game/

  vite.config.ts
  tsconfig.json

    services/

      saveService.ts
      leaderboardService.ts
    ui/

      layout.ts
```

## Этап 3. Перенос данных машин

Статус: готово, см. `docs/phaser-car-assets-audit.md`.

Источник:

```text
game/cars_data.py
assets/cars/
```

Нужно:

1. Преобразовать `game/cars_data.py` в `src/data/cars.ts` или `src/data/cars.json`: готово, см. `yandex-game/src/data/cars.ts`.
2. Сохранить поля:
   - `name`;
   - `rarity`;
   - `value`;
   - `baseChance`;
   - `points`;
   - `imageKey`.
3. Проверить, что каждая машина имеет изображение: готово, пропусков нет.
4. Привести имена файлов ассетов к стабильным ключам: готово, используется `imageKey` в формате `car:<id>` и фактический `imageFile`.

Пример модели:

```ts
export type Rarity =
  | "Обычный"
  | "Необычный"
  | "Редкий"
  | "Эпический"
  | "Легендарный"
  | "Эксклюзивный";

export type Car = {
  id: string;
  name: string;
  rarity: Rarity;
  value: number;
  baseChance: number;
  points: number;
  imageKey: string;
};
```

## Этап 4. Перенос игрового ядра

Статус: готово, см. `docs/phaser-core-port.md`.

Python-модули:

```text
game/engine.py
game/models.py
storage/db.py
```

Новая логика:

```text
src/game/spinEngine.ts
src/game/caseEngine.ts
src/game/economy.ts
src/game/saveModel.ts
```

Важно: игровое ядро лучше не привязывать к Phaser. Phaser должен отвечать за сцены, ввод, анимации и отображение. RNG, кейсы, экономика и сохранения должны быть обычными TypeScript-функциями или классами.

## Этап 5. Игровые сцены

### BootScene

- Инициализация базовых настроек.
- Инициализация Yandex Games SDK.
- Загрузка сохранения игрока.
- Переход в `PreloadScene`.

### PreloadScene

- Загрузка изображений машин.
- Загрузка UI-ассетов.
- Экран прогресса загрузки.

### MenuScene

- Баланс игрока.
- Главное меню:
  - крутить;
  - гараж;
  - кейсы;
  - улучшения;
  - лидерборд.

### SpinScene

- Кнопка спина.
- Анимация выпадения машины.
- Карточка машины.
- Действия:
  - оставить;
  - продать.

### GarageScene

- Сетка машин.
- Сортировка по редкости и цене.
- Просмотр карточки машины.
- Продажа машины.
- Показ заполненности гаража.

### CasesScene

- Необычный+ кейс.
- Редкий+ кейс.
- Эксклюзивные кейсы.
- Открытие x1, x10, x100.
- Автоматическая обработка результата при заполненном гараже.

### UpgradesScene

- Улучшение множителя шанса.
- Расширение гаража.
- Отображение стоимости следующего улучшения.

### LeaderboardScene

- Показ топа через Yandex Leaderboards.
- Отправка результата игрока.

## Этап 6. Сохранения

SQLite из Telegram-версии в web-версии не используется.

Модель сохранения:

```ts
export type SaveData = {
  version: number;
  money: number;
  chanceMult: number;
  garageCap: number;
  inventory: {
    inventoryId: string;
    carId: string;
    obtainedAt: number;
  }[];
  stats: {
    spins: number;
    casesOpened: number;
    carsSold: number;
  };
};
```

Логика:

1. При старте игры попробовать загрузить данные через Yandex Player Data.
2. Если SDK недоступен или игрок не авторизован, использовать `localStorage`.
3. После важных действий сохранять прогресс:
   - выпадение машины;
   - продажа;
   - открытие кейса;
   - покупка улучшения;
   - изменение гаража.
4. Добавить поле `version`, чтобы в будущем делать миграции сохранений.

## Этап 7. Интеграция Yandex Games SDK

Создать обертку:

```text
src/services/yandexSdk.ts
```

Она должна закрывать прямое обращение к SDK:

```ts
export type YandexSdkService = {
  init(): Promise<void>;
  loadPlayerData(): Promise<SaveData | null>;
  savePlayerData(data: SaveData): Promise<void>;
  showFullscreenAd(): Promise<void>;
  showRewardedAd(): Promise<boolean>;
  submitLeaderboardScore(score: number): Promise<void>;
};
```

SDK-слой должен иметь fallback-режим для локальной разработки, чтобы игра запускалась через `npm run dev` без Яндекс Игр.

## Этап 8. Лидерборд

Текущий Telegram-бот считает лидерборд из SQLite.

В Phaser-версии лучше считать рейтинг так:

```text
score = сумма points всех машин в гараже
```

После изменения гаража:

1. Пересчитать `score`.
2. Отправить результат в Yandex Leaderboards.
3. При открытии экрана лидерборда запросить топ игроков.

## Этап 9. Реклама и монетизация

Для первого релиза можно добавить только базовую рекламу.

Fullscreen-реклама:

- между сессиями;
- после нескольких спинов;
- после открытия серии кейсов.

Rewarded-реклама:

- бесплатный кейс;
- временный бонус к шансу;
- бонус денег;
- дополнительное место в гараже на ограниченное время или как награда.

Важно: игра должна ставиться на паузу во время рекламы и корректно продолжаться после закрытия.

## Этап 10. UX и визуальная адаптация

Telegram-бот текстовый, а Яндекс Игры требуют ощущения полноценной игры.

Нужно сделать:

1. Карточки машин с изображениями.
2. Цвета редкостей.
3. Анимацию спина.
4. Гараж как коллекцию.
5. Внятный экран загрузки.
6. Адаптацию под мобильные экраны.
7. Крупные кнопки для touch-управления.
8. Быстрый возврат в главное меню из любой сцены.

## Этап 11. Подготовка к публикации

Перед загрузкой в Яндекс Игры:

1. Проверить запуск локально.
2. Проверить production-сборку:

```bash
npm run build
```

3. Проверить папку `dist/`.
4. Проверить работу без Telegram, Python и SQLite.
5. Проверить работу сохранений.
6. Проверить iframe-режим.
7. Проверить мобильный viewport.
8. Проверить, что SDK инициализируется до использования сервисов Яндекса.
9. Проверить паузу при рекламе.
10. Загрузить `dist/` в консоль Яндекс Игр.

8. Сделать улучшения.

## Минимальный первый релиз

Чтобы быстрее дойти до рабочей версии, первый релиз можно ограничить так:

- главное меню;
- спин;
- карточка выпавшей машины;
- оставить или продать;
- гараж;
- улучшение шанса;
- расширение гаража;
- сохранение прогресса;
- базовый лидерборд.

Кейсы, rewarded-реклама, платежи и события можно добавить после того, как базовая игра пройдет техническую проверку.

## Главный принцип миграции

Не переносить Telegram-бот один в один. Нужно перенести игровую математику и данные, но сделать новую визуальную оболочку под web-игру. Phaser-версия должна ощущаться как самостоятельная браузерная игра, а не как бот с кнопками.
